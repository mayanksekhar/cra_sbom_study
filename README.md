# SBOM and VEX quality study for the EU Cyber Resilience Act

Independent research project. Unreviewed draft. Author: Mayank Sekhar (GitHub: mayanksekhar). Last updated 2026-11-08.

## What this is
An empirical study of where correctness is lost between an SBOM and a vulnerability finding. It covers 53 project versions (pilot in five ecosystems, then Go, Maven, PyPI, Rust and npm sets of 3 to 10 projects each), three SBOM generators (Syft, Trivy, cdxgen), scoring with Grype, Trivy and OSV Scanner used in controls, a reachability oracle for Go (govulncheck) and OpenVEX statements. Every missed finding is attributed to a cause. The results are mapped to Regulation (EU) 2024/2847 and to BSI TR-03183-2.

## Status and limits (read this first)
1. This is a draft that has not been peer reviewed. There is no preprint yet.
2. The numbers in the draft are checked by scripts against the CSV files in this repository. Several statements rest on one or two projects and are marked as such.
3. The reachability rate depends on a single static oracle that has no independent check yet. A blind agreement check is planned on the decidable cards of a 40 card sample (at most 18: 6 with a direct import, 13 reached through an import chain, minus one card whose answer the author saw). It tests the oracle on those cards, not the whole rate.
4. The regulation was read in the EUR-Lex consolidated English text, which has no legal effect. The BSI guideline was read from a mirror copy. Nothing here is legal advice or a legal interpretation.
5. Errors found and claims withdrawn during the work are logged in docs/pilot_findings.md.

## Contents
1. docs/draft.md, docs/draft_section7.md, docs/draft_front_back.md: the draft text, with status marks (V verified, P partial, O open).
2. docs/cra_mapping.md: mapping of results to the regulation and to BSI TR-03183-2.
3. docs/claims_audit.md and docs/pilot_findings.md: what is claimed, how it was checked, and the corrections.
4. docs/table_findings.md and docs/progress.csv: a generated results table and the progress rubric.
5. harness/: scripts that fetch, generate, scan, score and check. dataset/: pinned project lists with commit hashes. tools/: tool versions and database checksums.
6. results*/: small summary files only. The raw outputs are in a separate data archive.
7. labels/label_sample.csv: the 40 row sample for the reachability check. It contains the oracle's answer, so it is not a blind sheet.

## Check the numbers
    python3 harness/check_all.py
Without the data archive five of seven checks run and two are skipped with a message. With the archive all seven run. See docs/REPRODUCE.md.

## Data archive
The archive holds SBOMs generated by three tools for pinned versions of third party open source projects, and scanner outputs, in a sanitized form: the author's home path was replaced by a relative path or ~/, the host name by "host", the author's email address by author@example.invalid, and consumer mailbox addresses (165 gmail.com, 1 qq.com) by redacted@<domain>. Nine OSV Scanner output files are empty on purpose (they record tool crashes or no output) and are listed in docs/REPRODUCE.md. The archive embeds advisory text and project metadata from third parties. Their licences continue to apply and have not been reviewed here.
