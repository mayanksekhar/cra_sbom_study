# SBOM and VEX quality study for the EU Cyber Resilience Act

Independent research project. Unreviewed draft. Author: Mayank Sekhar (GitHub: mayanksekhar). Last updated 2026-11-17.

## What this is
An empirical study of where correctness is lost between an SBOM and a vulnerability finding. It covers 61 project versions (pilot in five ecosystems, then Go, Maven, PyPI, Rust and npm sets of 8 to 11 projects each), three SBOM generators (Syft, Trivy, cdxgen), scoring with Grype, Trivy and OSV Scanner used in controls, a reachability oracle for Go (govulncheck) and OpenVEX statements. Every missed finding is attributed to a cause. The results are mapped to Regulation (EU) 2024/2847 and to BSI TR-03183-2.

## Labelling protocol
The output of the reachability oracle (govulncheck) is public in this repository (results_go/reach.json), so the blindness of the manual agreement check cannot rest on secrecy. The labelling therefore follows a protocol. Each labeller receives only the cards file, by a private channel and never the repository or the data archive, works offline with harness/label_cli.py (which shows no tool verdict) and opens no repository file until every card is answered. The verdicts file stays private until all labellers have finished. harness/label_score.py then compares the verdicts with the private answer key; cards that were not blind for a labeller are excluded with its --skip option and counted in the paper. The finish date of each labeller is recorded in docs/pilot_findings.md.

## Status and limits (read this first)
1. This is a draft that has not been peer reviewed. There is no preprint yet.
2. The numbers in the draft are checked by scripts against the CSV files in this repository. Several statements rest on one or two projects and are marked as such.
3. The reachability rate depends on a single static oracle that has no independent check yet. A blind agreement check is planned on the decidable cards of a 40 card sample (at most 18: 6 with a direct import, 13 reached through an import chain, minus one card whose answer the author saw). It tests the oracle on those cards, not the whole rate.
4. The regulation was read in the EUR-Lex consolidated English text, which has no legal effect. The BSI guideline was read from a mirror copy. Nothing here is legal advice or a legal interpretation.
5. Errors found and claims withdrawn during the work are logged in docs/pilot_findings.md.

    python3 harness/check_all.py

## Data archive
Published: the archive is attached to the release data-20261119 of this repository; bash harness/fetch_data.sh downloads it and checks the SHA256. It holds SBOMs generated by three tools for pinned versions of third party open source projects, and scanner outputs, for all sets (pilot, older pins, Go, Maven, PyPI, Rust, npm). It holds every untracked file under results*/ (3180 files in seven folders: results 529, results_go 575, results_mvn 376, results_npm 583, results_old 353, results_py 340, results_rust 424). The tracked summary files stay in the repository and are not repeated in it. Image archives of the container set, source checkouts and the vulnerability databases are not in it.

It is sanitized. The author's home path was replaced by a relative path or `~/`, the host name by `host`, the author's email address by `author@example.invalid`, consumer mailbox addresses (170 replacements) by `redacted@` followed by the original domain, and every other personal address (298 replacements) by `redacted@redacted.invalid`. Role addresses of advisory sources (the NVD, MITRE and GitHub advisory senders, for example), example addresses and version strings that look like addresses are kept on purpose (124 distinct forms in 406 files). Thirteen OSV Scanner output files are empty on purpose (5 tool crashes, 8 with no output) and are listed in docs/REPRODUCE.md. The archive is built by harness/build_archive.py, which checks that no trace of the replaced strings is left and that every JSON file still parses. The archive embeds advisory text and project metadata from third parties. Their licences continue to apply and have not been reviewed here.
